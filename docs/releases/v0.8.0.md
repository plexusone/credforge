# v0.8.0

**Release Date:** 2026-11-22

## Highlights

- **`credforge generate` makes the values a tool can make.** For each
  credential whose `generation.format` is set, it makes a random value
  or a private key and puts it in every primary store:
    - **Only where missing.** It finds what is missing by name, never
      reading a value, and makes a credential only when none of its
      primary stores holds one. A parameter is created only if it still
      does not exist, so a value is never replaced.
    - **Never shown.** The value is made in memory with `crypto/rand`,
      written, and recorded as `created`. It is never printed.
    - **Asks first.** It lists what it will make and what it leaves, and
      why.

## Added

- Formats: `hex32` and `base64url32` (32 random bytes), and `p256-pem`,
  `ed25519-pem` and `rsa3072-pem` (a PKCS #8 private key).
- `--only` for a pattern of credential IDs, `--include-planned` for an
  environment being brought up, `--dry-run`, `--yes` and `--by`.
- In Go: `credforge.Generator`, `Generates`, `NewValue`, the `Creator`
  interface with `ErrExists`, `awsssm.Writer.Create`, and `cli.Generate`
  to mount the command in a host tool.

## Changed

- Requires systemspec-credential v0.4.0, for `generation.format`.

## Upgrading

No change is needed to check, install or review. To generate, add
`generation.format` to the credentials a tool should make, with either
no provisioner or one whose tool is `credforge generate`. A credential
whose provisioner is another tool is left to that tool. Writing needs
`ssm:PutParameter` and `kms:Encrypt` on the parameters' key, as install
does.
