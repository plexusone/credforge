# v0.7.0

**Release Date:** 2026-11-21

## Highlights

- **`credforge install` sets a value everywhere it belongs, and records
  it.** One command replaces setting a secret in each repository by hand
  and recording it afterwards:
    - It lists the stores it will write and asks before it reads the
      value.
    - It reads the value once, hidden, from the terminal. The value is
      never an argument, never written to disk and never printed.
    - It checks the value before writing anything. A GitHub token must
      read each repository its entitlements name, so a missing
      repository, an organization's pending approval or an expired token
      stops the install with the reason.
    - It records `created`, or `rotated` when the log already has a
      value, with the expiry GitHub reports or the one you give, then
      `verified` with the checks that passed.

## Added

- Writes to GitHub Actions repository secrets, sealed with the
  repository's public key, and to AWS SSM parameters as `SecureString`.
- `--dry-run` to list the writes, `--expires` to set the expiry, `--by`
  for the events, `--no-probe` to skip the check, and `--stdin --yes` for
  a value piped in.
- In Go: `credforge.Installer` with its `Writer` and `Prober` interfaces,
  `github.Prober`, `github.Client.Write`, `awsssm.Writer`, and
  `cli.Install` to mount the command in a host tool.

## Changed

- A GitHub request GitHub refuses, other than 404, is returned as a
  `*github.StatusError` carrying its status code. The message is
  unchanged.

## Upgrading

No change is needed to check or review. To install, the GitHub token in
the targets file's environment variable needs write access to each
repository's secrets (the `repo` scope, or Secrets: read and write), and
the AWS profile needs `ssm:PutParameter` and `kms:Encrypt` on the
parameters' key. A credential that a provisioner makes and stores is
refused; run its command instead.
