# v0.9.0

**Release Date:** 2026-11-22

## Highlights

- **`credforge setup` makes setting up credentials a runbook.** It builds
  a [systemspec-runbook](https://github.com/plexusone/systemspec-runbook)
  runbook from the registry for one system and environment, and runs it:
    - **From the registry alone.** A phase per need (launch, then later and
      optional), with steps in the setup order: prerequisites at issuers,
      a step for each tool's command, one for every value `generate`
      makes, and for each credential from an issuer its console, steps,
      the exact access to give it, `install` and its configuration
      changes. Improving an entry improves the runbook.
    - **Checked without values.** Each step is checked with
      `credforge check --only <credential>`, which reads names only.
    - **Run step by step.** `run` asks before each command, waits while
      you do the issuer's part, then checks and records the step.
    - **Rendered.** `doc` writes Markdown, or HTML with `--html`.

## Added

- `credforge setup --system <system> [--env <env>] [--need launch,later,optional]`
  with `list`, `show`, `run`, `verify`, `record`, `doc` and `export` (the
  runbook as JSON). Progress is kept in `setup-<system>-<env>.json` beside
  the event log, or where `--progress` says.
- In Go: `runbook.Build`, `cli.Setup`, `Options.Tool` for how the
  runbook's commands run credforge when mounted in a host tool, and
  `ValueNames`.

## Changed

- `install` refuses a credential whose primary stores are named for
  different values, such as an OAuth client's secret and its ID. It
  would otherwise write the same value to both. Give each value its own
  credential; the setup runbook says so in the step.
- Requires systemspec-runbook v0.1.0.

## Upgrading

No change is needed to check, generate, install or review. A host tool
that mounts `cli.Setup` sets `Options.Tool` to its own command, such as
`["bin/infra", "credentials"]`, so the runbook's commands run through it.
