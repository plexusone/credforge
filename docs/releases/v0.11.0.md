# v0.11.0

**Release Date:** 2026-11-23

## Highlights

- **Signing in with the GitHub CLI is enough.** `check`, `review` and
  `install` use the token `gh` is signed in with when neither
  `GITHUB_TOKEN` nor `GH_TOKEN` is set, so there is nothing to export
  before a run.

## Added

- A GitHub binding without `tokenEnv` looks for its token in
  `GITHUB_TOKEN`, then `GH_TOKEN`, then asks `gh auth token`. If none
  gives one, the error says to set a variable or sign in with
  `gh auth login`.
- A binding that names `tokenEnv` still uses only that variable, so a
  targets file can insist on a particular token.
- `github.Token` returns the token in that order, for programs using the
  package directly. `github.TokenFromEnv` is unchanged.

## Changed

- The setup runbook's access section names the GitHub CLI's sign-in and
  no longer asks for `export GITHUB_TOKEN=$(gh auth token)`.

## Documentation

- The README, the overview and Getting Started drop the token export.
  Getting Started says when the GitHub CLI's sign-in is used, and its
  example binding no longer names `tokenEnv`.

## Upgrading

No change is needed. A targets file whose GitHub binding sets
`"tokenEnv": "GITHUB_TOKEN"` keeps working but gets no fallback; remove
`tokenEnv` to use the GitHub CLI's sign-in when the variable is unset.
Regenerate setup runbooks to drop the export from their access section.
