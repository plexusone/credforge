## [v0.5.0] - 2026-11-20

### Highlights

- The review page's Setup list shows each credential left to set up: where to get it, what it may do and where to put it

### Added

- Review page: a Setup list view grouped by system and environment, a To set up by hand tile and a To set up by filter; after a live check it leaves out what is already in place ([`0429865`](https://github.com/plexusone/credforge/commit/0429865))

## [v0.4.0] - 2026-11-20

### Highlights

- The review page shows who handles each credential's generate, distribute and rotate stages: a human operator, an agent operator or a program

### Added

- Review page: a Handled by column with each stage's actor, and a filter matching credentials with any stage handled that way ([`0d8d388`](https://github.com/plexusone/credforge/commit/0d8d388))

### Dependencies

## [v0.3.0] - 2026-11-20

### Highlights

- `credforge review` serves a local page to review every credential with its live state, and saves decisions and events

### Added

- Reviews file (`review.File`): one decision per credential or store key, approved, change or remove, with a generated JSON Schema ([`71d31dd`](https://github.com/plexusone/credforge/commit/71d31dd))
- `review.Server`: the review page and its API, answering only to a loopback Host and same-origin JSON writes ([`0a54d97`](https://github.com/plexusone/credforge/commit/0a54d97))
- `credforge review` and `cli.Review`, served on a loopback address only; `Options.ReviewsPath` and `Options.Title` ([`fba577f`](https://github.com/plexusone/credforge/commit/fba577f))

### Documentation

- README describes the review page and mounting `cli.Review`

## [v0.2.0] - 2026-11-20

### Highlights

- `cli.Check` mounts the check command alone in a host tool's command tree, beside systemspec-credential's commands

### Added

- `cli.Check`, the check command with its own `--registry`, `--events` and `--targets` flags, which take precedence over a parent's flags of the same names ([`64812ec`](https://github.com/plexusone/credforge/commit/64812ec))

### Documentation

- README shows mounting `cli.Check`; the roadmap marks Phase 1 done

## [v0.1.0] - 2026-11-20

### Highlights

- Check a systemspec-credential registry and its event log against the stores and consumers it names, reporting each store as missing, stale, unregistered, changed, unrecorded, unlisted, unobserved or present
- No value is ever read: observers list names and when each was last set, and no type has a field for a value
- Read-only: installing and rotating values through OmniVault providers follows

### Added

- `Compare`, a pure comparison of a registry, its event log and what was observed, with a grace for events recorded after the change, and `Check`, which derives the scopes to list from the registry ([`33ccbda`](https://github.com/plexusone/credforge/commit/33ccbda))
- `Record`, which logs unrecorded stores as `created` and changed ones as `deployed` at the store's time, never editing the registry ([`b0c96ad`](https://github.com/plexusone/credforge/commit/b0c96ad))
- Targets file binding store types and accounts to connections, with a JSON Schema generated from the Go types ([`ae08bae`](https://github.com/plexusone/credforge/commit/ae08bae))
- GitHub observers: a repository's Actions secret names and when each was set, and its workflows' `secrets.NAME` references ([`f81a351`](https://github.com/plexusone/credforge/commit/f81a351))
- AWS Systems Manager Parameter Store observer: names and last change with `DescribeParameters`, one directory level at a time ([`39b1cc2`](https://github.com/plexusone/credforge/commit/39b1cc2))
- `credforge check` with text and JSON output, `--record`, `--fail-on`, `--only` and `--include-planned`, `credforge schema targets`, and `cli.New` for mounting in a host tool ([`944945b`](https://github.com/plexusone/credforge/commit/944945b))

### Documentation

- Product and technical requirements, plan and roadmap for INIT-CREDFORGE-001 ([`1e888dc`](https://github.com/plexusone/credforge/commit/1e888dc))
- README, documentation site and v0.1.0 release notes

### Infrastructure

- CI, lint and CodeQL workflows and lint configuration ([`86e1bbd`](https://github.com/plexusone/credforge/commit/86e1bbd))
- Keep LF line endings on every platform, so the generated targets schema matches its source on Windows
